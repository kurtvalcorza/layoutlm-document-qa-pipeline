## What changed from the inference-only tutorial

The previous notebook (`TASK-INFERENCE`) answered five authored questions over one rendered invoice and reported `sample-sanity` ANLS/exact-match for that page. This notebook keeps that page and its inference contract as Section 5 and adds the adaptation contract around it: a real annotated receipt corpus read one column at a time, corpus-level metrics in the carried `metrics.py`, two non-neural baselines, a fit check that drops rather than truncates, a bounded fine-tuning, a per-field breakdown, the invoice re-read after adaptation, and an artifact that reloads. The per-page `evaluation_report` helper is unchanged; `pipe.evaluate` is the corpus-level stage (`measured` / `measured-small-sample`).

## Conformance notes

- **Standalone carrier (ST1–ST8):** the primary path performs no clone, repository install, or repository import. Section 2 embeds the repository's 3 modules verbatim in topological dependency order (each tagged `metadata.dimer.embedded_module`; the only rewrites make `DEFAULT_WEIGHTS_DIR` working-directory-relative and remove internal relative package imports), Section 3 carries the 8-file snapshot manifest inline and asserts it against the module's constants before fetching, and `NOTEBOOK_SOURCE` records the repository, revision and module digests in the exports.
- **Parity (PAR1–PAR4):** `tests/test_notebook_parity.py` and `tools/validate_release_assets.py` fail when the carried modules, the inline manifest, or the inline pins differ from the repository, or when the notebook is not byte-identical to the generator's output.
- **Model acquisition (MOD1–MOD9):** `stage_missing_files(WEIGHTS_DIR, allow_download=True)` fetches only the manifest entries a fresh clone lacks (the git-ignored `model.safetensors`), at the pinned revision; `verify_snapshot` re-hashes every entry; `LayoutLMDocumentQAPipeline.from_pretrained(weights_dir=WEIGHTS_DIR)` loads the verified files (`local_files_only=True`, `trust_remote_code=False`); no pickle is opened anywhere (the upstream `pytorch_model.bin` and `tf_model.h5` are not listed); no cell outside the carried modules calls `huggingface_hub`, `transformers`, `pyarrow`, `safetensors` or `urllib`; **no OCR dependency is installed**.
- **Data (DAT1–DAT9, ST6):** the default sample is the `ground_truth` column of two objects in the Hub dataset repository `naver-clova-ix/cord-v2` at the immutable revision `7f0115a4b758a71d6473b8d085751692da2fef98` (`data/test-…parquet`, 234,202,795 bytes, SHA-256 `51c65f17…`; `data/validation-…parquet`, 242,080,800 bytes, SHA-256 `0d0f6dac…`). For each file the declared size and SHA-256 are checked against the pins through the Hub's file metadata before any byte is read, only the parquet footer and that column are fetched over HTTPS range requests through `pyarrow` (about 0.4 MB in total; no image is downloaded), and the decoded column is refused unless its own SHA-256 matches the pin. Rows become pages (words in line order, boxes the clipped hull of each annotated quadrilateral, `is_key` words excluded from answers), pages become templated questions (one per field category on exactly one line; *first item* = the topmost single-line `menu.nm`), the one receipt whose words repeat another shard's is dropped, and the 199 unique receipts are cut **by receipt** into 119 / 30 / 50 pages (`check_split_disjoint` asserts no shared page id and no shared word sequence). The template adds a second *External access* bullet naming the repository, the revision, the two files, the byte counts and the CC BY 4.0 licence.
- **Fit check (VAL6):** the window ceiling needs the real tokenizer, so after the model loads `pipe.check_fit` partitions each split into the records whose question + page fit one 512-token window and the ids that would be windowed at inference; the dropped ids are printed and recorded in the evaluation report (the build record dropped none), and nothing is truncated.
- **Stages (§4.1):** `fetch_corpus` + `read_corpus` + `build_sample_dataset` / `load_byod_dataset` + `split_dataset` (sample acquisition) → `validate_dataset` + `check_split_disjoint` + refusal probes (validation, with three digests) → `check_fit` → `validate_inputs` + `pipe.answer` with sanity checks + `evaluation_report` on the rendered invoice (inference contract) → `last_number_baseline` + `keyword_lookup_baseline` + `pipe.evaluate` on the frozen model with the per-field breakdown (baselines) → `pipe.adapt` (bounded fine-tuning) → `pipe.evaluate` on validation and test with the comparison (evaluation) → `pipe.answer` + `evaluation_report` on the invoice again (inference) → `pipe.save_artifact` → `LayoutLMDocumentQAPipeline.from_artifact` with the parity assertion (export and reload).
- **Score semantics (UNC1–UNC4):** every per-answer score is the product of the start and end softmax probabilities of the chosen span within its window — a within-page ranking signal, not a calibrated probability and never an answerability signal; ANLS and exact match are corpus-level agreement with gold spans under DocVQA's normalisation (own implementations); no rejection threshold ships. The invoice re-read is scored with a `sample-sanity` verdict that names the missing dispersion.
- **Baselines and evidence (EVAL6/EVAL10/EVAL11):** the last-number and keyword-lookup baselines and the frozen model are scored on the same 229 test questions as the adapted model, every metric is labelled as one seeded split of one corpus with no dispersion estimate, and the notebook says explicitly that CORD's annotated words and boxes are cleaner than any OCR engine's output on a photographed receipt.
- **Split integrity (SPL1–SPL8):** the split is seeded and page-disjoint by id and by content; validation selects the epoch and the test split is used for nothing but the final evaluation; the notebook states that pages from few sources must be split by source.
- **Ceilings (VAL6):** `MIN_IMAGE_SIDE` (1), `MAX_IMAGE_SIDE` (10000), `MAX_WORDS` (2000), `MAX_QUESTION_CHARS` (256), `MAX_SEQ_LEN` (512), `DOC_STRIDE` (128), `MAX_ANSWER_TOKENS` (15), `BOX_GRID` (1000), the record bounds (8..20,000) and the id pattern are stated in the Prerequisites and printed before the model runs; four dataset refusals and one input refusal are demonstrated.
- **BYOD (DAT10–DAT19):** `USE_BYOD` defaults to `False` so the sample path never opens an upload dialog; when enabled, user records flow through the same validation, page-disjoint split, fit check, baselines, fine-tuning, evaluation, export and reload cells. The expected schema and the privacy guidance — an internal document set with its field annotations is restricted data — are stated in the Prerequisites and in Section 4, and the training split is written to `outputs/layoutlm_document_qa_train.jsonl` in the JSONL shape.

- `tools/validate_release_assets.py` performs source validation only.
